# review

review strengths, weaknesses, risks and test gaps; findings sorted by file/line, one per line with a concrete fix. When the project has design, test-plan or security/privacy documents, check the work against them too. For a security-sensitive change, when the project has a chosen security audit tool or skill, run it on the change alongside review and weigh its findings; the project picks the tool, snail requires none. Read-only: report findings and stop. Only if fixes were requested or in auto: fix every finding and re-review; if the same finding survives 3 passes, stop and report.
